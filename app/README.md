# Калькулятор A + Рейтинг команд (десктоп)

Десктоп-приложение на Python + Tkinter с вкладками:

1. **Калькулятор A** — исходный экран расчёта `A` по коэффициентам дома/гости.
2. **Рейтинг команд** — расчёт рейтинга команд и коэффициента силы по коэффициентам `1/X/2`.
3. **Справочник команд** — лиги и команды из Supabase (`config/supabase.json`), логотипы локально. См. `docs/supabase-teams-spec.md`.
4. **Счет кэф** — Shin-модель P1/X/P2.
5. **История** — просмотр сохранённых сезонов и матчей из Supabase (`v_season_summary`, `v_matches_full`). См. `docs/supabase-history-spec.md`.
6. **Линия (голы)** — голевая модель Poisson / Dixon-Coles: из исторических
   closing-линий (азиатские форы + тоталы + 1X2) строит матрицу счетов и весь
   набор рынков. См. ниже.

## Вкладка «Линия (голы)» — модель из closing-линий

Идея: `closing lines → скрытые S_m, D_m → λ_h, λ_a → матрица счетов → все рынки`.

Модули: `app/goal_model.py` (ядро) и `app/goal_model_train.py` (обучение + CLI).

Этапы:

1. **De-vig**: все рынки (Over/Under, AH, 1X2) — методом **Shin** (общий z на исходы рынка; для 2 и 3 исходов).
2. **Восстановление скрытых параметров матча**:
   - `S_m = λ_h + λ_a` из тотала и Over/Under (сумма голов ~ Pois(S),
     подбор по условной P(Over | не возврат));
   - `D_m = λ_h − λ_a` из азиатской форы и AH-odds (полная матрица счетов,
     учёт возвратов и четвертных линий .25/.75);
   - `λ_h = (S+D)/2`, `λ_a = (S−D)/2`.
3. **Рейтинг силы** `D_m = r_home − r_away + H·I_home` — robust WLS (Huber),
   нормировка `Σ r = 0`, веса по дате/качеству/дерби/нейтрали и размеру форы.
4. **Attack/Defense** `log λ = μ + A − Df + H_g·I_home` — robust WLS,
   `Σ A = 0`, `Σ Df = 0`.
5. **Калибровка** `D_final = a + b·D_model`, `S_final = c + d·S_model`,
   Dixon-Coles `γ` — подгонка матрицы под 1X2 (Shin), Nelder–Mead,
   вес ничьей `draw_loss_weight`.
6. **Модель ничьей** (отдельная): `logit(P_X) = α + β_D·|D| + β_S·S + β_S2·S² +
   β_DxS·|D|·S`, взвешенный МНК по `logit(px_Shin)` (веса включают надёжность
   рынка 1X2 `W_1X2`). В прогнозе целевая `P_X^target` **корректирует диагональ**
   матрицы: `diag × q` (q клампится в `[0.85; 1.15]`), недиагональ × c — сумма
   остаётся 1. Вся линия выходит из одной финальной матрицы.
7. **Прогноз**: `λ_h, λ_a → матрица P(i,j) → коррекция ничьи → 1X2, тоталы, форы,
   индивидуальные тоталы, точный счёт`, центральные линии, опц. маржа.

CSV-формат (заголовок, алиасы поддерживаются):

```
date,league,home_team,away_team,closing_ah_home,closing_total_line,
ah_home_odds,ah_away_odds,over_odds,under_odds,
home_odds,draw_odds,away_odds,neutral_flag,derby_flag,quality_flag,value,derby_weight,neutral_weight
```

Веса матча: сезон (настройки программы) × **value** × **derby_weight** × **neutral_weight**
(столбцы CSV, по умолчанию 1.0) × размер форы `w_line_AH = 1/(1+α_AH·|D|^p)` × экстремальность тотала
`w_line_T = 1/(1+α_T·(S−S̄)²)` × robust-Huber (считается на итерациях).

CLI:

```bash
# обучить + спрогнозировать матч
python3 app/goal_model_train.py train \
  --input docs/examples/closing_lines_serie_a_sample.csv \
  --home Inter --away Empoli

# walk-forward валидация (§16): обучение на прошлом, прогноз следующего матча
python3 app/goal_model_train.py validate \
  --input docs/examples/closing_lines_serie_a_sample.csv --min-train 12
```

Walk-forward даёт MAE форы/тотала и сравнение P1/X/П2 с Shin (плюс смещение
ничьи). Диагностика рейтинга (`strength_diagnostics`) выдаёт по матчам
`D_market`, `D_model`, ошибку и веса — для поиска выбросов.

Пример данных: `docs/examples/closing_lines_serie_a_sample.csv`.

Редактируемые **веса сезонов** (§3/§18) — и на десктопе, и на iOS:
строки `дата_от, дата_до, вес` + default, плюс кнопка **«Пересчитать»**.
Множители качества/дерби/нейтраль задаются **в CSV** (столбцы `value`, `derby_weight`,
`neutral_weight`). Сезонный вес ищется по диапазону дат матча.

**iOS (Safari):** та же модель портирована в `web/FairOddsCalc_iOS.html` —
вкладка **«Линия»** (версия `goal-model-v1`): вставка/загрузка CSV, обучение,
редактируемые α форы/тотала, prior α, q_min/q_max ничьи, веса сезонов, флаги
«Модель ничьи»/«Dixon-Coles», выбор команд (нейтраль/дерби, маржа), все рынки.
Числа совпадают с десктопом (worked-пример Inter–Roma, Inter–Empoli).

## Что считает

Для каждой строки:

```
A = (Коэф гости − 1) / (Коэф дома − 1)
```

Перед усреднением выполняется **фильтр аномальных выбросов по IQR** (метод Тьюки ×1.5), затем «Средняя А» считается по «чистым» значениям выбранным методом.

### Фильтр аномалий (IQR ×1.5)

1. Собрать все `A`, отсортировать по возрастанию.
2. `Q1` = перцентиль 0.25, `Q3` = перцентиль 0.75 (линейная интерполяция).
3. `IQR = Q3 − Q1`.
4. Границы: `lower = Q1 − 1.5·IQR`, `upper = Q3 + 1.5·IQR`.
5. Аномалия: `A < lower` **или** `A > upper`.
6. Аномальные строки помечаются в колонке `A` красным с пометкой `✕` и **исключаются** из расчёта.

Итоговый коэффициент = среднее (по умолчанию **геометрическое**) по неаномальным значениям. Чекбокс «Исключать аномалии (IQR ×1.5)» позволяет отключить фильтр (например, для сравнения). При `n < 4` фильтр не применяется (квартили неустойчивы).

## Рейтинг команд — робастная оценка

Помимо обычного МНК, доступна **робастная оценка** домашнего преимущества `H` и рейтингов (флаг `--robust` в CLI и чекбокс «Робастная оценка» во вкладке рейтинга):

- **Информационный вес**: матчи с экстремальными коэффициентами (разгромы, `E→0/1`) дают меньший вес — там `D_market` шумные из-за насыщения Elo-шкалы. `w_info = 4·E_home·E_away` (1.0 для ровного матча, →0 для разгромного).
- **IRLS-Huber по остаткам**: матчи, которые модель не может объяснить (большой `residual = D − (R_home − R_away + H)`), автоматически давятся; порог по MAD остатков (c = 1.345).
- Отчёт показывает `H` (робастное) vs `H (OLS)`, сдвиг и список задавленных матчей.

Зачем: «большой `|D|`» — это не выброс (разгром реален), а **шумное** наблюдение; настоящие аномалии видны по **остаткам**. Поэтому фильтруем не по значению (как IQR для средней `A`), а робастной регрессией по остаткам.

```bash
python3 app/team_ranking.py --input matches.csv --robust --top 10
```

### Логика расчёта рейтинга

Для каждого матча:

1. `p1_raw = 1/odds_1`, `px_raw = 1/odds_x`, `p2_raw = 1/odds_2`
2. `overround = p1_raw + px_raw + p2_raw`
3. `p1 = p1_raw/overround`, `px = px_raw/overround`, `p2 = p2_raw/overround`
4. `E_home = p1 + 0.5*px`, `E_away = p2 + 0.5*px`
5. `D_market = 400 * log10(E_home / E_away)`
6. Уравнение: `R_home - R_away + H = D_market`

После всех матчей система решается в МНК с нормировкой `sum(R_team)=0`.

На выходе:

- рейтинг команд `R_team` (по убыванию);
- коэффициент силы `StrengthCoef = 10^(R_team/400)`;
- оценка домашнего преимущества `H` и его мультипликатор `10^(H/400)`.

### Формат входного CSV

Нужны команды и коэффициенты 1/X/2. Поддерживаются заголовки:

- команды: `home_team`, `away_team` (алиасы: `home`, `away`, `team1`, `team2`);
- коэффициенты: `odds_1`, `odds_x`, `odds_2` (алиасы: `p1`, `x`, `p2`, `1odds`, `xodds`, `2odds`).

Также поддерживается CSV **без заголовка**: первая строка может быть сразу данными в порядке:

`home_team,away_team,odds_1,odds_x,odds_2`

Пример работает с файлом:

```bash

```

1. Выберите **лигу** и **сезон** (`2024-25`).
2. **Загрузить CSV…** — файл в формате Excel-таблицы (сразу сохраняется в хранилище).

### Логика расчётов на истории

- **Приор `H`**: по каждому хранимому сезону считается `H` (робастный МНК из
  `team_ranking`), затем берётся экспоненциально-взвешенное среднее (свежие
  сезоны весомее, вес `exp(-xi*k)`). Если есть матчи текущего сезона — усадка
  `H = w·H_current + (1−w)·H_prior`, `w = m/(m+κ)`; при `m ≤ 2` или несвязном
  графе берётся только приор. Нет истории → константа лиги (`LEAGUE_DEFAULT_H`).
- **draw-модель** `px(d) = clamp(a + b·|d|, 0.06, 0.34)`: линейная регрессия
  доли ничьих по `|D_market|` (по фактическим результатам; при их отсутствии —
  по de-vig вероятности ничьей). Используется для разбиения `E_home` на `p1`/`px`
  в прогнозах через общих соперников.

Это даёт корректный league-specific `H` для цепочек/переворота площадки и
откалиброванную ничью вместо «магической» константы `k_draw`.

## Методы усреднения

| Метод | Формула |
|-------|---------|
| Среднеарифметическое | `Σ Aᵢ / n` |
| Геометрическое | `exp( mean( ln Aᵢ ) )` |
| Линейное усечённое 5% | отбросить 5% значений с каждого края, затем среднее |
| Усечённо-геометрическое 5% | усечение 5% в лог-пространстве, затем `exp(среднее)` |

При малом `n` усечение 5% не отбрасывает элементов (`int(n·0.05)=0`) и совпадает с полным средним — это корректно.

> Фильтр IQR и усечение 5% — независимые механизмы: сначала IQR убирает аномалии, затем выбранный метод (включая усечённый) применяется к оставшимся значениям.
