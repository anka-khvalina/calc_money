Рекомендация по умолчанию — три периода по «возрасту» относительно последнего тура:

            

              
Период (дней назад)ВесЗачем

              
                
0–60 — последние ~2 месяца1.0актуальная форма и состав

                
61–120 — предыдущие ~2 месяца0.8ещё релевантно, но слабее

Проверено walk-forward на 13 лига-сезонах Big-5 (264 сравнения, обучение до даты отсечки → прогноз следующих 40 матчей, метрика — отклонение от closing):

            
    
              
  • Тоталы (S) выигрывают от спада веса: 1.0/0.7/0.4 → MAE_S −4.8%, экспоненциальный спад с полураспадом 30–60 дней → −7…−9.6%.
    • 
              
  • Форы (D) почти не меняются у мягких схем (±0.1%), но портятся при слишком быстром спаде: полураспад 45 дней → +1.2%, 30 дней → +3.0% ошибки.
    • 
              
  • Лучший компромисс — 1.0 / 0.8 / 0.6 (границы 60/120): D −0.07%, S −2.6%.
    • 
              
  • По лигам: Premier League любит короткий горизонт (D −2.6% при полураспаде 30 дней), Serie A — ровные веса, La Liga / Bundesliga / Ligue 1 — мягкий спад.

FairOddsCalc — что это

      
Приложение строит футбольную линию из исторических closing-коэффициентов.
      Итог — комбинация двух независимых моделей на одной active-выборке:

      

        
Рынок в UIМодельМатрица

        
          
1X2 (П1 / X / П2)LegacyPoisson + Dixon–Coles (γ)

          
AH / OU (фора и тотал)AutoMarginals (α) + Gaussian Copula (ρ)

        
      

      

        active closing → общие веса → обучить Legacy + Auto → прогноз → 1X2 из Legacy · AH/OU из Auto
      

      
Пользователь не выбирает «победителя»: обе модели обучаются одной кнопкой, в результат попадают разные рынки.
      λh, λa — ожидаемые голы хозяев/гостей; S = λh+λa; D = λh−λa.


      
Вкладки

      
    
        
  • Линия — загрузка active-матчей, обучение обеих моделей, расчёт комбинированной линии.
    • 
        
  • Справочник — команды по лигам (и логотипы).
    • 
        
  • История — сезоны и матчи Supabase (правки → потом перезагрузка и переобучение).
    • 
        
  • Отчёты — calculated vs closing на inactive / motivation=нет: те же правила (1X2 Legacy, AH/OU Auto).
    • 
        
  • Справка — этот раздел.
    •

Азиатская фора — знак (как у бука)

      

        
closing_ah_home — фора на хозяев, в БД хранится без смены знака:

        
    
          
  • Минус (−0.75, −1, …) — хозяева сильнее, отдают голы форой.
    • 
          
  • Плюс (+0.5, …) — хозяева слабее, получают фору.
    • 
          
  • AH1 выше AH2 на минусовой линии — нормально: покрыть жёсткую фору сложнее, чем просто выиграть.
    • 
        

        
Программа подставляет линию как в БД в расчёт покрытия. Отдельно подбирается D = λh−λa (обычно D>0, если хозяева сильнее) — это не «перевёрнутая» фора в базе.

        
margin = (голы хозяев − голы гостей) + closing_ah_home
# margin > 0 → хозяева покрыли (с учётом push на .0 / четвертных)

      


      
Как обучается модель

      
Кнопка «Обучить модель» запускает два независимых пайплайна на одной active-выборке и одних весах
      (season × match_weight × neutral × training_weight). Рейтинги Legacy и Auto не общие — у каждой модели свой fit.

      

        
    
          
  1. Общая подготовка матчей (Shin → market S/D → веса) — одинаковая логика для обеих.
    2. 
          
  2. Legacy (calculateLegacyModel): сила r → атака/оборона → калибровка S/D → подбор γ Dixon–Coles → книги Dynamic D / S-EMA / SFA.
    3. 
          
  3. Auto (calculateAutoModel / gmTrain): сила r → атака/оборона → калибровка S/D → подбор α, ρ → Auto 1X2-калибровка (только внутри Auto) → те же динамические книги.
    4. 
        

      

      
В UI рейтинги/сводка обычно берутся из Auto; чипы показывают «1X2 Legacy» и «AH/OU Auto», когда оба train прошли.


      
0. Что должно быть в матче

      
Обязательно: фора + AH1/AH2 + тотал + Over/Under. Без этого матч не идёт в обучение.  
      Желательно: 1/X/2, веса, is_neutral.


      
1. Снятие маржи (везде Shin)

      
Все рынки — форы, тоталы и 1X2 — очищаются от маржи методом Shin
      (подбирается параметр z, общий для исходов рынка):

      
pi(z) = ( √(z² + 4(1−z)·qi²) − z ) / (2(1−z)) ,  qi = 1/Ki
# z подбирается так, чтобы Σ p_i = 1 (для 2 и для 3 исходов)
# Over 2.5 @1.91 / Under @1.99  →  P(Over) ≈ 0.511


      
2. Восстановление скрытых S и D

      
S — ожидаемая сумма голов λh+λa. Не равна просто линии тотала: подбирается по Over/Under.

      
S = argmin ( Pмодель(Over | S) − PfairOver )²

      
D — ожидаемая разница λh−λa. Подбирается по линии форы как у бука и AH1/AH2 (четвертные линии, push).

      
D = argmin ( Pмодель(покрыли AH | S, D) − PfairAH home )²
λh = (S + D) / 2 ,   λa = (S − D) / 2

      
Пример: Inter–Roma, тотал 2.5, фора −0.75 → S≈2.72, D≈0.82.  
      Пример с жёсткой форой: −1 @ AH1 2.83 / AH2 1.49 → P(покрытия) < 50%, D всё равно > 0, но меньше, чем на −0.5.


      
3. Рейтинг силы команд

      
Dm = rхозяева − rгости + Hleague·Iдома + δderby·Iдерби + ε
# взвешенный МНК (Huber), Σ r = 0
# δ_derby оценивается при ≥3 дерби в выборке; shrinkage w = n/(n+τ), τ=30


      
4. Атака и оборона

      
log λh = μ + Aхозяева − Dfгости + Hg
log λa = μ + Aгости − Dfхозяева
# Σ A = 0, Σ Df = 0; A — атака, Df — оборона


      
5. Калибровка под 1X2 (у каждой модели своя)

      
Dcal = dA + dB·Dмодель
Scal = sA + sB·Sмодель

      
Legacy дополнительно подбирает γ Dixon–Coles. Auto — без DC; после выбора α/ρ может перекалибровать dA/dB (и при необходимости sA/sB) на joint matrix (auto1x2Calib). Это улучшает Auto для AH/OU; итоговый 1X2 в UI всё равно из Legacy.


      
6. Score matrix — две разные

      
# Legacy (для 1X2)
λh, λa → Poisson → Dixon–Coles(γ) → P(i,j)
P1 / PX / P2 = треугольники + диагональ

# Auto (для AH / OU)
λh, λa → Marginals (Poisson при α=0 / NegBin при α>0)
→ Gaussian Copula (ρ) → joint P(i,j)

      
α и ρ калибруются автоматически по лиге. Отдельная draw-model в продукте выключена.


      
Политика весов при обучении

      
wbase = Wсезон × match_weight × neutral_mult × wrotation
# neutral_mult = neutral_weight только если нейтральное поле = да

      
При прогнозе дерби меняет Heff, не вес:

      
Heff = 0                         # нейтраль
Heff = Hleague                 # обычный матч
Heff = shrink(Hleague + δ)       # дерби (δ из обучения)
Dpred = rh − ra + Heff

Итоговые веса по этапам (политика D: AH Line Weight выключен, lineWeight.mode=disabled):

      
wсила (D) = wbase × wHuber
# AH line weight не участвует в обучении Goal Difference

wатака (S) = wbase × wline тотал × wHuber
wline тотал = clamp( 1 / (1 + αтотала·(S−S̄)²), 0.3, 1 )

      
Прогноз и расчёт коэффициентов не меняются. Huber по-прежнему ослабляет выбросы на обучении D. Экстремальный тотал по-прежнему режет вес на этапе S.


      
Прогноз («Рассчитать линию»)

      
Кнопка считает два прогноза с одним набором флагов (нейтраль/дерби/дата/сезон), затем склеивает рынки:

      

        
    
          
  1. Общий core внутри каждой модели (gmCoreSdLambdas): рейтинги → Dynamic D → S-EMA → калибровка → SFA (на D) → SFTC (на S) → λh, λa.
    2. 
          
  2. Legacy (irPredictLegacy): Poisson(λ) → Dixon–Coles(γ, в т.ч. dynamic γ по |D|) → 1X2.
    3. 
          
  3. Auto (gmPredict): Marginals(α) + Copula(ρ) → AH и OU (центральные линии).
    4.

Dynamic D и State Aging (подбор D)

      
После базового рейтинга к D добавляется Dynamic D — slow/fast EMA остатков рынка.
      Aging ослабляет эти EMA, если команда долго не играла (длинный перерыв / старт сезона).

      

        
    
          
  1. 1 Dbase = rh − ra + Heff (рейтинги не стареют).
    2. 
          
  2. 2 У каждой команды в книге Dynamic D две EMA: slow (α≈0.12) и fast (α≈0.40), walk-forward по истории.
    3. 
          
  3. 3 Bias слоя: bias = clamp(EMA · n/(n+K), ±maxAbs) (shrink + min_observations).
    4. 
          
  4. 4 Aging (если dynamic_d.state_aging.enabled): для каждой команды
            AF = 2^(−days / H), затем EMA_aged = EMA × AF (и slow, и fast).
            days = дней с прошлого матча этой команды до даты расчёта;
            на «Линии» дата = inactive-сравнение или сегодня. H = half_life_days (сейчас 60).
    5. 
          
  5. 5 Поправка матча:
            ΔD = (slowh−slowa) + (fasth−fasta),
            clamp по total.max_abs (≈0.60) → Ddyn = Dbase + ΔD.
    6. 
          
  6. 6 Дальше как обычно: калибровка dA/dB → SFA → λ. Aging не трогает r, A/Df, cal, SFA.
    7. 
        

      

      
AF = 2−days/H     # H=60 → через 60 дней AF=0.5; через 120 → 0.25
EMAaged = EMA · AF   # отдельно home/away, slow и fast
Ddyn = Dbase + ΔD(EMAaged)

      
Конфиг: d_correction (slow/fast) + dynamic_d.state_aging.
      Аналогично для тоталов: dynamic_s / S-EMA × свой AF (dynamic_s.state_aging).
      Если aging выключен — AF=1, поведение как раньше (только Dynamic D без старения).

Советы и частые вопросы

      
    
        
  • Имена команд в справочнике должны совпадать с матчами в БД, иначе применится рейтинг новичка.
    • 
        
  • Фора в БД — на хозяев, знак как у бука; программа знак при расчёте не переворачивает.
    • 
        
  • Нейтральное поле и Нейтр. вес — разные вещи: первое отключает H, второе ослабляет вклад строки при обучении.
    • 
        
  • Дерби по умолчанию выключено у всех матчей. Отметьте в Истории → ▼ Веса → перезагрузите и переобучите модель.
    • 
        
  • Низкая мотивация → Мотивация = нет в Истории (матч вне обучения; на Отчёте серый, без MAE). Мягко ослабить вклад: уменьшите match_weight.
    • 
        
  • После правок в Истории — «Загрузить из БД», затем снова «Обучить модель» (пересчитываются и Legacy, и Auto).
    • 
        
  • «Нужно ≥2 матчей» — мало загруженных матчей или не заполнены обязательные рынки.
    • 
        
  • 1X2 «из Auto» в UI нет — Auto может калиброваться по 1X2 внутри себя, но на экране П1/X/П2 всегда из Legacy.
    • 
        
  • Где хранятся данные: матчи, коэффициенты и веса — в Supabase. Локально в Safari (localStorage) — логотипы, история расчётов на «Линии», мелкие UI-настройки. Обученная модель — в памяти вкладки: после F5 снова «Загрузить из БД» → «Обучить модель».
    • 
        
  • Открывайте в Safari напрямую, не во встроенном браузере мессенджера.
    •
