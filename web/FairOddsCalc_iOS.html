FairOddsCalc — что это

      
Приложение строит футбольную линию (1X2, азиатские форы, тоталы, индивидуальные тоталы, точный счёт)
      из исторических закрывающих (closing) коэффициентов. Всё считается из одной матрицы счетов,
      поэтому рынки согласованы между собой.

      

        история closing-линий → скрытые S, D → λh, λa → матрица P(i,j) → коррекция ничьи → вся линия
      

      
λh, λa — ожидаемые голы хозяев/гостей; S = λh+λa; D = λh−λa; i, j — голы хозяев и гостей.


      
Вкладки

      
    
        
  • Линия — обучение модели и расчёт линии матча (главная вкладка).
    • 
        
  • Справочник — команды по лигам (и логотипы). Списки команд в «Линии» берутся отсюда.
    • 
        
  • История — просмотр сохранённых сезонов и матчей из Supabase. Отсюда данные можно загрузить в «Линию».
    • 
        
  • Отчёт inactive — сравнение расчётных коэффициентов с эталоном по неактивным матчам (read-only, без изменения БД).
    • 
        
  • Справка — этот раздел.
    •

Поля матча (Supabase → модель)

      
Для обучения из v_matches_full используются closing-линии и веса:

      
    
        
  • home_team_id, away_team_id — идентификаторы команд из справочника team. Модель опирается на id, а не на имя, поэтому переименование команды в справочнике не ломает рейтинги и прогноз.
    • 
        
  • home_team, away_team — имена (для отображения). В интерфейсе команда всегда показывается как id — название.
    • 
        
  • closing_ah_home + ah_home_odds / ah_away_odds — фора.
    • 
        
  • closing_total_line + over_odds / under_odds — тотал.
    • 
        
  • home_odds / draw_odds / away_odds — 1X2 (калибровка).
    • 
        
  • match_weight — вес матча (по умолчанию 1).
    • 
        
  • Нейтральное поле (is_neutral) — факт: матч был на нейтральном? При «да» нет домашнего преимущества.
    • 
        
  • Нейтр. вес (neutral_weight) — коэффициент ослабления при обучении; учитывается только если нейтральное поле = да (обычно 0,8).
    • 
          
  • Дерби — факт (да/нет); в БД derby_weight = 1 или 0. Поправка к H считается при обучении.
    • 
      

      
Команды и лиги в модели хранятся по id (рейтинги, атака, оборона). Имена берутся из карты team_names только для подписей. CSV-импорт без колонок *_team_id использует имя как ключ (совместимость со старым форматом).

Азиатская фора — знак (как у бука)

      

        
closing_ah_home — фора на хозяев, в БД хранится без смены знака:

        
    
          
  • Минус (−0.75, −1, …) — хозяева сильнее, отдают голы форой.
    • 
          
  • Плюс (+0.5, …) — хозяева слабее, получают фору.
    • 
          
  • AH1 выше AH2 на минусовой линии — нормально: покрыть жёсткую фору сложнее, чем просто выиграть.
    • 
        

        
Программа подставляет линию как в БД в расчёт покрытия. Отдельно подбирается D = λh−λa (обычно D>0, если хозяева сильнее) — это не «перевёрнутая» фора в базе.

        
margin = (голы хозяев − голы гостей) + closing_ah_home
# margin > 0 → хозяева покрыли (с учётом push на .0 / четвертных)

      


      
Как обучается модель

      
Цепочка для каждого матча истории, затем сводная регрессия по всей выборке.


      
0. Что должно быть в матче

      
Обязательно: фора + AH1/AH2 + тотал + Over/Under. Без этого матч не идёт в обучение.  
      Желательно: 1/X/2, веса, is_neutral.


      
1. Снятие маржи (везде Shin)

      
Все рынки — форы, тоталы и 1X2 — очищаются от маржи методом Shin
      (подбирается параметр z, общий для исходов рынка):

      
pi(z) = ( √(z² + 4(1−z)·qi²) − z ) / (2(1−z)) ,  qi = 1/Ki
# z подбирается так, чтобы Σ p_i = 1 (для 2 и для 3 исходов)
# Over 2.5 @1.91 / Under @1.99  →  P(Over) ≈ 0.511


      
2. Восстановление скрытых S и D

      
S — ожидаемая сумма голов λh+λa. Не равна просто линии тотала: подбирается по Over/Under.

      
S = argmin ( Pмодель(Over | S) − PfairOver )²

      
D — ожидаемая разница λh−λa. Подбирается по линии форы как у бука и AH1/AH2 (четвертные линии, push).

      
D = argmin ( Pмодель(покрыли AH | S, D) − PfairAH home )²
λh = (S + D) / 2 ,   λa = (S − D) / 2

      
Пример: Inter–Roma, тотал 2.5, фора −0.75 → S≈2.72, D≈0.82.  
      Пример с жёсткой форой: −1 @ AH1 2.83 / AH2 1.49 → P(покрытия) < 50%, D всё равно > 0, но меньше, чем на −0.5.


      
3. Рейтинг силы команд

      
Dm = rхозяева − rгости + Hleague·Iдома + δderby·Iдерби + ε
# взвешенный МНК (Huber), Σ r = 0
# δ_derby оценивается при ≥3 дерби в выборке; shrinkage w = n/(n+τ), τ=30


      
4. Атака и оборона

      
log λh = μ + Aхозяева − Dfгости + Hg
log λa = μ + Aгости − Dfхозяева
# Σ A = 0, Σ Df = 0; A — атака, Df — оборона


      
5. Калибровка под 1X2

      
Dfinal = a + b·Dмодель
Sfinal = c + d·Sмодель
# + Dixon-Coles γ для счетов 0:0, 1:0, 0:1, 1:1


      
6. Модель ничьи и коррекция матрицы

      
logit(PX) = α + βD·|D| + βS·S + βS2·S² + βD×S·|D|·S
PXtarget = 1 / (1 + e−logit)

      
Целевая ничья корректирует диагональ матрицы (кламп qmin…qmax):

      
q = clamp( PXtarget / PXматрица , qmin , qmax )
P'(i,i) = q·P(i,i) ,   P'(i,j) = c·P(i,j)   # сумма снова = 1


      
Веса матча при обучении

      
wbase = Wсезон × match_weight × neutral_mult
# neutral_mult = neutral_weight только если нейтральное поле = да

      
При прогнозе дерби меняет Heff, не вес:

      
Heff = 0                         # нейтраль
Heff = Hleague                 # обычный матч
Heff = shrink(Hleague + δ)       # дерби (δ из обучения)
Dpred = rh − ra + Heff

      

        
МножительГде задаётсяПример

        
          
Wсезонтаблица весов на «Линии»прошлый сезон 0.7

          
match_weightИстория → «Вес»низкая мотивация 0.5 (бывш. CSV value)

          
ДербиИстория → ▼ Весафлаг 1/0; δderby при обучении, Heff при прогнозе

          
neutral_weightИстория → ▼ Веса0.8, только если нейтральное поле = да

        
      

      
Метка low_motivation в note — только заметка; в формулу входит число match_weight.  
      0 — матч исключён из обучения.

      
Дополнительно (автоматически в коде):

      
wсила = wbase × wline AH × wHuber
wline AH = clamp( 1 / (1 + αфоры·|D|²), 0.15, 1 )

wатака = wbase × wline тотал × wHuber
wline тотал = clamp( 1 / (1 + αтотала·(S−S̄)²), 0.3, 1 )

      
Большой перевес по форе / экстремальный тотал → матч слабее влияет на соответствующий этап. Huber ослабляет выбросы по остаткам.


      
Прогноз («Рассчитать линию»)

      

        
    
          
  1. Берём рейтинги r, атаку/оборону A, Df обученной модели.
    2. 
          
  2. Считаем Heff (нейтраль → 0; дерби → shrink(H+δ); иначе Hleague).
    3. 
          
  3. Считаем Dpred = rh−ra + Heff.
    4. 
          
  4. Считаем Spred из log-модели голов + калибровка a,b,c,d.
    5. 
          
  5. λh, λa → пуассоновская матрица P(i,j).
    6. 
          
  6. Опционально: Dixon–Coles, коррекция ничьи (qmin…qmax).
    7. 
          
  7. Из одной матрицы: 1X2, тоталы, форы (знак как у бука), ИТ, топ счетов.
    8. 
        

      

      
P(i,j) = Pois(i; λh) · Pois(j; λa)
П1 = Σi>j P ,  X = Σi=j P ,  П2 = Σi<j P
Kчестный = 1/P ,   Kс маржой = 1 / (P·(1+маржа%))

      
Команда не участвовала в обучении → рейтинг новичка (среднее N слабейших). Имена — из Справочника.  
      «Центральная» фора/тотал — линия с примерно равными кэфами (поиск по матрице).


      
Справочник настроек («Линия»)

      

        
НастройкаНа что влияет

        
          
α форыПриглушение матчей с большим перевесом сил при обучении рейтинга. Больше → крупные форы влияют меньше.

          
α тоталаПриглушение матчей с экстремальным тоталом при обучении атаки/обороны.

          
prior αПри повторном «Обучить модель» стягивает рейтинги и A/Df к предыдущей модели (0.7 = 70%). Первое обучение — без prior.

          
q_min / q_maxПредел изменения ничьи из матрицы (±10% по умолчанию). 0.85–1.15 — только для экспериментов.

          
Модель ничьиВкл — отдельная модель ничьи + коррекция диагонали. Выкл — ничья как из Пуассона.

          
Dixon-ColesПоправка низких счетов (0:0, 1:0, 0:1, 1:1).

          
match_weight / neutral_weightВеса матча (▼ Веса). Дерби меняет H при прогнозе, не вес.

          
Веса сезоновМножитель для каждого выбранного сезона при загрузке из Supabase.

          
новичок: N слабейшихКоманде без матчей рейтинг = среднее N слабейших команд лиги.

          
Нейтраль / Дерби / МаржаПараметры конкретного прогноза: без домашнего преимущества / дерби / кэфы с маржой.

Советы и частые вопросы

      
    
        
  • Имена команд в справочнике должны совпадать с матчами в БД, иначе применится рейтинг новичка.
    • 
        
  • Фора в БД — на хозяев, знак как у бука; программа знак при расчёте не переворачивает.
    • 
        
  • Нейтральное поле и Нейтр. вес — разные вещи: первое отключает H, второе ослабляет вклад строки при обучении.
    • 
        
  • Дерби по умолчанию выключено у всех матчей. Отметьте в Истории → ▼ Веса → перезагрузите и переобучите модель.
    • 
        
  • Низкая мотивация → уменьшите match_weight в Истории (не отдельный флаг).
    • 
        
  • После правок в Истории — «Загрузить из БД», затем снова «Обучить модель» (каждое нажатие пересчитывает коэффициенты по текущим данным).
    • 
        
  • «Нужно ≥2 матчей» — мало загруженных матчей или не заполнены обязательные рынки.
    • 
        
  • Где хранятся данные: матчи, коэффициенты и веса — в Supabase (общие для всех устройств с доступом к БД). Локально в Safari (localStorage) — только логотипы команд, история расчётов на «Линии» и мелкие настройки UI. Обученная модель живёт в памяти вкладки — после перезагрузки страницы снова «Загрузить из БД» → «Обучить модель».
    • 
        
  • Открывайте в Safari напрямую, не во встроенном браузере мессенджера.
    •
