# Объём MVP (первая версия кода)

Границы первой реализуемой версии десктоп-приложения после согласования документации в `docs/`.

**Review gate:** код начинается только после явного OK по документам и закрытия критичных пунктов [open-questions.md](open-questions.md).

---

## Включено в MVP

### Расчёт

| ID | Функция |
|----|---------|
| CALC-1 | Полная логика **сценария 1** (сезоны, рыночный вес, venue, без FlipRule) |
| CALC-2 | Полная логика **сценария 2** = S1 + пересечение через C |
| CALC-3 | Выбор сценария: окно 90 дней, подходящий C, откат при ненадёжности |
| CALC-4 | De-vig пропорциональный |
| CALC-5 | Наложение маржи на вывод (уровни 1–5) |
| CALC-6 | Перевертыши и `k_derby` только в S2 |
| CALC-7 | Слияние S1 и оценки пересечения (γ по умолчанию 0.6) |

### Данные

| ID | Функция |
|----|---------|
| DATA-1 | Импорт CSV: matches, team_strength, venue_factors, flip_rules |
| DATA-2 | Валидация по [data-model.md](data-model.md) |

### UI

| ID | Функция |
|----|---------|

|----|---------|

## Не входит в документацию v1 / выбор на этапе кода

- Конкретный GUI-фреймворк (Qt, Tauri, Electron, …).
- Платформы: Windows / macOS / Linux — уточнить при старте кода.
- Авторизация, облако, мультипользовательский режим.

---

## Критерии готовности MVP

1. Импорт примеров из [examples/](examples/) без ошибок.
2. Расчёт для пары A–B воспроизводит числовые примеры [calculation.md](calculation.md) с допустимой погрешностью ±0.01 на k.
3. При отсутствии C — сценарий 1 с корректным `scenario_reason`.
4. При наличии C и надёжности — сценарий 2; при CV > порога — откат S1.
5. UI показывает три режима коэффициентов и маржу 1–5.
6. Документация `docs/` согласована с заказчиком (review gate пройден).
