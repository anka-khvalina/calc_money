# Обучение и расчёт линии — подробная справка

Полное описание голевой модели во вкладке **«Линия»** (web/iOS и desktop).  
Краткие формулы: [calculation.md](calculation.md). Маппинги БД: [reference.md](reference.md).  
Встроенная копия для пользователя: вкладка **«Справка»** в `FairOddsCalc_iOS.html`.

---

## 1. Идея: когда Legacy, когда Auto

Из **closing-коэффициентов** прошлых матчей программа учит **две независимые модели** на **одной** active-выборке (одинаковые веса):

| Рынок в UI | Модель | Матрица | Когда используется |
|------------|--------|---------|-------------------|
| Home / Draw / Away | **Legacy** | Poisson + Dixon–Coles (γ) | «Рассчитать линию», Отчёт |
| Asian Handicap | **Auto** | Marginals (α) + Gaussian Copula (ρ) | «Рассчитать линию», Отчёт |
| Over / Under | **Auto** | то же | «Рассчитать линию», Отчёт |

Пользователь **не выбирает** «победителя». Одна кнопка **«Обучить модель»** запускает оба пайплайна; **«Рассчитать линию»** считает оба прогноза и **склеивает рынки**.

```text
История матчей (Supabase, active, без motivation=нет)
    → Shin de-vig → market S/D → общие веса
    ├── Legacy train (свой r, A/Df, cal, γ, Dynamic D/S, SFA)
    └── Auto   train (свой r, A/Df, cal, α/ρ, Dynamic D/S, SFA)

Прогноз матча
    → у каждой модели: gmCoreSdLambdas (D/S dynamics → cal → SFA → SFTC → λ)
    ├── Legacy matrix → 1X2 в UI
    └── Auto matrix   → AH / OU в UI
```

**Важно:** рейтинги Legacy и Auto **не общие** — это два независимых fit на одних данных. λ (и SFA) могут чуть отличаться; в комбинированном результате 1X2 берётся из Legacy, AH/OU — из Auto.

Вкладка **«Отчет»** сравнивает ту же комбинированную линию с closing на `active=false` и на `motivation=false` (серые строки; кэфы считаются, MAE/выводы — без них). Обучение на Отчёте и на «Линии» не берёт `motivation=false`.

## 2. Какие данные нужны

### Обязательно для обучения (каждый матч)

| Поле БД | UI | Смысл |
|---------|-----|--------|
| `home_team`, `away_team` | Хоз / Гост | имена как в справочнике |
| `closing_ah_home` | AH | линия форы **на хозяев** |
| `ah_home_odds`, `ah_away_odds` | AH1, AH2 | кэфы на покрытие форы |
| `closing_total_line` | Тот | линия тотала |
| `over_odds`, `under_odds` | O, U | кэфы тотала |

Матч **не попадает в обучение**, если нет полной линии (фора + тотал + все четыре кэфа).

### Желательно

| Поле | Зачем |
|------|--------|
| `home_odds`, `draw_odds`, `away_odds` | калибровка S/D под 1X2; качество выборки |
| `is_neutral` | без домашнего преимущества в этом матче (`H_eff = 0`) |
| `match_weight` | качество матча (мягкое ослабление, напр. 0.5) |
| `motivation` | `false`/«нет» → матч **вне обучения**; на Отчёте серый (кэфы да, MAE нет). `null` = в обучении |
| `derby_weight` | **флаг дерби**: `1` = да, `0` / `null` = нет; поправка к **H** при обучении |
| `neutral_weight` | ослабление веса при обучении, **только** если `is_neutral` |
| `note` | заметка (`low_motivation`) — **не влияет на формулу** |

### Вес сезона

На вкладке **«Линия»** — таблица весов по `season_id` (после загрузки из БД).  
Default: 1.0 для каждого выбранного сезона.

## 3. Азиатская фора — знак и смысл

**В БД хранится как у букмекера** (`closing_ah_home` — фора на хозяев):

| Линия | Кто сильнее | Пример |
|-------|-------------|--------|
| **−0.75, −1, …** | хозяева фаворит | Inter −1 @ AH1 2.83 / AH2 1.49 |
| **+0.25, +0.5, …** | хозяева аутсайдер | |

**Высокий AH1 при минусовой линии** — нормально: покрыть жёсткую фору сложнее, чем выиграть «в ноль» на 1X2.

**Программа не меняет знак линии** при основном расчёте:

```text
P_fair(AH home) = Shin de-vig(AH1, AH2)
D = подбор так, чтобы P(хозяева покрыли фору | S, D) = P_fair
```

Линия **−1** подставляется в формулу покрытия **как есть**.  
Внутренний параметр **D = λ_h − λ_a** (ожидаемая разница голов) обычно **положительный**, если хозяева сильнее — это не то же самое, что знак в БД.

Покрытие форы (счёт `i:j` у хозяев):

```text
margin = (i − j) + closing_ah_home
```

margin > 0 → хозяева покрыли (с учётом push на целых/четвертных линиях).

**Запасной путь** (нет AH-кэфов, только линия): `D ≈ −closing_ah_home`.

## 4. Обучение — по шагам

### Шаг 0. Загрузка и двойной train

1. Лига + сезоны → **«Загрузить из БД»**.
2. Проверка: внизу число матчей «к обучению допущено».
3. При необходимости — веса сезонов → **«Обучить модель»**.

Внутри `goalRunTrain`:

```text
gmModelLegacy = calculateLegacyModel(raw, cfg_legacy, inactive)
gmModelAuto   = calculateAutoModel(raw, cfg_auto, inactive)
```

Обе модели строятся на **одной** active-выборке. Inactive подтягиваются в книги динамики (история EMA), но не в WLS-обучение силы.

### Шаг 1. Shin de-vig (каждый матч)

Для каждого рынка отдельно снимается маржа методом **Shin**:

- тотал: Over / Under  
- фора: AH1 / AH2  
- 1X2: 1 / X / 2  

Получаем честные вероятности `P_fair`, сумма = 1.

### Шаг 2. Скрытые S и D матча

**S** — ожидаемая сумма голов `λ_h + λ_a`:

```text
S = argmin ( fair_price_model(Over | S) − P_fair(Over) )²
```

`fair_price_model(Over)` — **не** обычная вероятность `P(G > line)`, а честная модельная цена азиатского тотала:

| Линия | Формула q |
|-------|-----------|
| **2.5** | `q = P(G ≥ 3)` |
| **2.0** | `q = P(G ≥ 3) / [P(G ≥ 3) + P(G ≤ 1)]` (push на 2 голах) |
| **2.25** | `W = P(G≥3)`, `L = P(G≤1) + ½·P(G=2)`, `q = W/(W+L)` |

Общий вид: `W = Σ P(G=g)·(full_win + ½·half_win)`, `L = Σ …·(full_loss + ½·half_loss)`, `q = W/(W+L)`.

Сумма голов `G ~ Pois(S)`. По линии тотала и de-vig Over/Under (не просто «линия = ожидание»).

**D** — ожидаемая разница `λ_h − λ_a`:

```text
D = argmin ( fair_price_model(AH home | S, D) − P_fair(AH home) )²
```

`fair_price_model(AH home)` — не просто `P(margin > 0)`, а честная модельная цена с азиатским settlement:

```text
margin = (голы хозяев − голы гостей) + closing_ah_home

простая линия:  margin > 0 → win;  margin = 0 → push;  margin < 0 → loss
четвертная:     −0.25 = ½·AH(0) + ½·AH(−0.5);  +0.75 = ½·AH(+0.5) + ½·AH(+1.0)

W = Σ P(i,j)·(full_win + ½·half_win)
L = Σ P(i,j)·(full_loss + ½·half_loss)
q = W / (W + L)
```

| Линия | Пример на счёте 0:0 |
|-------|---------------------|
| **0** | push → вне знаменателя |
| **−0.5** | loss (нет push на .5) |
| **−0.25** | half_loss (push на 0, loss на −0.5) |
| **+0.75** | full win; при 0:1 — half_loss (+0.5 loss, +1.0 push) |

Затем:

```text
λ_h = (S + D) / 2
λ_a = (S − D) / 2
D ← clamp(D, −S+ε, S−ε)
```

**Диагностика clamp D:** при обучении логируется и показывается в UI, сколько матчей упёрлись в границу (trim ≠ 0 или D на `±S±ε`). Если **>2%** выборки — возможен конфликт AH vs OU или ошибка в линиях.

Особенно важно смотреть clamp в контекстах (помечаются в UI и логе):

| Контекст | Критерий |
|----------|----------|
| **Новичок / мало матчей** | у команды ≤3 матчей в выборке |
| **Начало сезона** | матч в первых 25% по дате |
| **Дерби** | `derby_weight = 1`, не нейтраль |
| **Нейтраль** | `is_neutral = true` |

**Пример (Inter – Roma):** тотал 2.5, фора −0.75 → S ≈ 2.72, D ≈ 0.82 → λ_h ≈ 1.77, λ_a ≈ 0.95.

### Шаг 3. Веса матча

**Базовый вес:**

```text
w_base = season_weight × match_weight × neutral_mult × w_rotation

neutral_mult = is_neutral ? neutral_weight : 1.0
```

| Множитель | Откуда | Пример |
|-----------|--------|--------|
| `season_weight` | таблица на «Линии» | прошлый сезон 0.7 |
| `match_weight` | БД / «История» → Вес | низкая мотивация 0.5 |
| `neutral_weight` | БД, если нейтральное поле = да | 0.8 |
| `w_rotation` | rotation codes + config | none=1, middle=0.7, high=0 |

**Дерби не входит в вес.** В БД колонка `derby_weight` хранит флаг: **1** = дерби, **0** или пусто = не дерби.  
По умолчанию у всех матчей дерби **выключено**, пока не отметите в блоке **▼ Веса** на «Истории».

`match_weight = 0` — матч не влияет на обучение.  
Метка `low_motivation` в `note` — только для человека; в формулу входит **число** `match_weight`.

### Веса по периодам сезона (recency)

Массовая установка `match_weight` по датам — «История» → **Массовое управление весом матчей**.

Рекомендация по умолчанию (отсчёт от последнего тура сезона):

| Возраст матча | `match_weight` |
| --- | ---: |
| 0–60 дней | `1.0` |
| 61–120 дней | `0.8` |
| > 120 дней | `0.6` |

Если приоритет — тоталы: границы 30/90 дней и веса `1.0 / 0.7 / 0.4`.

Проверено walk-forward на 13 лига-сезонах Big-5 (264 сравнения, обучение до отсечки → следующие 40 матчей, метрика — отклонение от closing):

- **S (тоталы)** улучшается от спада: `1.0/0.7/0.4` → MAE_S −4.8 %; экспоненциальный спад с полураспадом 30–60 дней → −7…−9.6 %.
- **D (форы)** у мягких схем нейтрально (±0.1 %), при быстром спаде **хуже**: полураспад 45 дней → +1.2 %, 30 дней → +3.0 %.
- Лучший компромисс — `1.0 / 0.8 / 0.6` (границы 60/120): D −0.07 %, S −2.6 %.
- По лигам: Premier League — короткий горизонт полезен, Serie A — ровные веса, La Liga / Bundesliga / Ligue 1 — мягкий спад.

Ограничения: `0` — это исключение из обучения (используйте «Активен = нет» / «Мотивация = нет»); не опускайте вес ниже `0.4`; при выборке меньше ~100 матчей оставляйте `1.0`.

**Политика весов на этапе силы** (Goal Difference / рейтинг `r`):

```text
w = w_base × w_Huber
```

AH Line Weight **не используется** при обучении D (`lineWeight.mode=disabled`).  
Прогноз и расчёт коэффициентов не затрагиваются. Режимы `soft` / `current` остаются доступны в конфиге для экспериментов.

**На этапе атаки/обороны** (Total Goals / S — без изменений):

```text
w_line_T = clamp( 1 / (1 + α_T · (S − S̄)²), 0.3, 1 )
w = w_base × w_line_T × w_Huber
```

Экстремальный тотал → меньший вес (default α_T = 0.5).

`w_Huber` — робастность: выбросы по остаткам ослабляются (итеративный Huber).

### Шаг 4. Рейтинг силы команд

Взвешенная регрессия (robust WLS):

```text
D_m ≈ r_home − r_away + H_league · I_home + δ_derby · I_derby_home
```

- `D_m` — разница из шага 2  
- `r_team` — сила команды (сумма по лиге = 0)  
- `H_league` — домашнее преимущество в обычных матчах  
- `I_home = 0` если `is_neutral`  
- `I_derby_home = 1` если матч дерби и не нейтральное поле  

**δ_derby** оценивается только если в выборке **≥ 3** дерби-матчей (default).  
Shrinkage: `δ_used = w · δ_raw`, `w = n_derby / (n_derby + τ)`, default `τ = 30`.

### Шаг 4b. Нейтральное поле vs нейтр. вес

| Поле | Что делает |
|------|------------|
| **Нейтральное поле** (`is_neutral`) | факт: матч на нейтрали? При «да» — **нет H** (`I_home = 0`), дерби-индикатор тоже 0 |
| **Нейтр. вес** (`neutral_weight`) | насколько доверять этому нетипичному матчу **при обучении** (множитель в `w_base`) |

Это разные вещи: нейтральное поле меняет **формулу**, нейтр. вес — только **вес** строки.  

### Шаг 5. Атака и оборона

```text
log λ_h = μ + A_home − Df_away + H_g · I_home
log λ_a = μ + A_away − Df_home
```

Σ A = 0, Σ Df = 0. Веса: `w_base × w_line_T × w_Huber`.

**L2-регуляризация** (без неё A/Df подгоняют шум — «сильная атака + дырявая оборона» от календаря):

```text
Loss = Σ w · (log λ − pred)² + λ_A · Σ A² + λ_Df · Σ Df²
```

Defaults: `λ_A = λ_Df = 0.10`. На рейтинги силы `r` отдельно: `λ_r = 0.10`.

### Шаг 6. Калибровка S/D под 1X2

Если есть 1X2 в истории:

```text
D_cal = dA + dB · D_model
S_cal = sA + sB · S_model
λ_h = (S_cal + D_cal) / 2
λ_a = (S_cal − D_cal) / 2
```

Имена: **dA/dB** — intercept/slope для D; **sA/sB** — для S (в конфиге режимы `dCalMode` / `sCalMode`). При `sCalMode=off` → sA=0, sB=1.

- **Legacy:** калибровка + подбор **γ** Dixon–Coles.  
- **Auto:** калибровка **без** DC.

**Контроль стабильности:** ожидается `dA≈0`, `dB≈1`, `sA≈0`, `sB≈1`. Сильные отклонения — сигнал, что база S/D слабая или мало данных.

### Шаг 6b. Auto 1X2 калибровка (только Auto)

После подбора `α` / `ρ` программа **перекалибрует** `dA,dB` (и при необходимости `sA,sB`) уже на итоговой joint matrix (`α,ρ`), без DC и без draw-model. Затем может уточнить `α/ρ` с приоритетом рынков **1X2 > AH > OU**.

Новая конфигурация принимается только если:

- MAE 1X2 улучшился;
- сумма |bias| по P1/PX/P2 уменьшилась;
- AH/OU не ухудшились больше чем `ahOuDegradeMaxPct` (default 5%).

Иначе остаётся baseline. Конфиг: `auto1x2Calib` в `model_config.json`.

Это улучшает **Auto-матрицу для AH/OU**. **Итоговый 1X2 в UI / Отчёте всегда из Legacy**, не из Auto.

### Шаг 7. Score matrix

#### Legacy

```text
λ_h, λ_a → Poisson → Dixon–Coles(γ)
P1 / PX / P2 из треугольников и диагонали
```

#### Auto Marginals + Gaussian Copula

```text
α=0 → Poisson-like; α>0 → Negative Binomial
ρ → зависимость голов через Gaussian Copula
P_draw = Σ_i P(i,i)   # без отдельной модели ничьи
```

NB (α) включается только если улучшение ≥ `nbMinImprovementPct` (default 1%) и матчей ≥ `minMatchesForLeagueAlpha` (default 200).
Copula (ρ) имеет **отдельный** порог `minMatchesForLeagueRho` (default 100): при 199 матчах α=0, но ρ всё ещё калибруется. Оба параметра обнуляются только если `n` ниже обоих порогов.

### Шаг 8. Динамические книги (после fit)

У **обеих** моделей строятся walk-forward книги:

| Книга | На что влияет при прогнозе |
|-------|----------------------------|
| **Dynamic D** (slow/fast EMA) | поправка к `D_base` |
| **S-EMA** | поправка к `S_base` |
| **SFA book** | Strong Favorite Adjustment на D |
| (опц.) inactive history | EMA видит прошлые матчи inactive, если переданы |

Конфиг: `d_correction` / `dynamic_d`, `dynamic_s_ema` / `dynamic_s` в `model_config.json`.

## 5. Прогноз матча («Рассчитать линию»)

### Вход

- Лига справочника, хозяева, гости (из **Справочника**).  
- Флаги: **нейтраль** (`H_eff = 0`), **дерби** (другое `H_eff`), **маржа %**.  
- `matchDate`: дата inactive-сравнения, если есть пара в БД; иначе **сегодня** (для aging).

### Общий core (у каждой модели свой fit)

Один путь `gmCoreSdLambdas` (Линия и Отчёт не расходятся по S/D/λ внутри модели):

```text
H_eff = effective_home_advantage(H_league, δ_derby, флаги)
D_base = r_home − r_away + H_eff
D_dyn  = D_base + DynamicD(slow/fast EMA × state_aging AF)
S_base = λ_h_AD + λ_a_AD          # из A/Df
S_dyn  = S_base + S_EMA × AF
D_cal  = dA + dB · D_dyn
S_cal  = sA + sB · S_dyn
D_final = SFA(D_cal)              # Strong Favorite Adjustment
S_final = SFTC(S_cal)             # Strong Favourite Total Correction (OU)
λ_h, λ_a = из (S_final, D_final), с λ_min
```

**H_eff при дерби:**

```text
H_eff = shrink(H_league + δ_used)     # если δ оценена (≥3 дерби в обучении)
H_eff = derbyDefaultFactor × H_league # мало дерби в обучении (default 0.7)
H_eff = H_league                      # не дерби
H_eff = 0                             # нейтраль
```

Команда без матчей в обучении → рейтинг **новичка** (среднее N слабейших в лиге).

### Dynamic State Aging

Если `dynamic_d.state_aging.enabled` / `dynamic_s.state_aging.enabled` (сейчас в деплое aging-on: **ON**, `half_life_days=60`):

```text
AF = 2^(−days_since_previous_match / H)
EMA_aged = EMA × AF
```

Старение применяется **только** к Dynamic D и S-EMA. Не трогает: рейтинги `r`, A/Df, калибровку dA/dB/sA/sB, SFA/SFTC thresholds.

### Матрицы и склейка рынков

```text
predL = irPredictLegacy(gmModelLegacy, …)   # Poisson + DC(γ)
predA = gmPredict(gmModelAuto, …)           # Marginals + Copula
combined = gmCombinePredictions(predL, predA)
```

| Рынок | Источник |
|-------|----------|
| 1X2 | Legacy matrix |
| AH line + odds | Auto matrix |
| OU line + odds | Auto matrix |

Программа **не** пересчитывает AH/OU на Legacy и **не** отдаёт 1X2 из Auto в пользовательский результат.

**Центральная линия** AH/OU — где кэфы сторон ≈ равны (поиск по Auto-матрице).

**С маржой:** `K = 1 / (p · (1 + margin))`.

SFTC влияет на **тотал Auto** (и показывается в мета-блоке прогноза). SFA для подписи 1X2 берётся в первую очередь из Legacy.

## 7. Частые вопросы

**Почему AH1 высокий при минусе на фаворите?**  
Рынок оценивает вероятность **покрытия форы**, а не просто победы. −1 @ 2.83 значит «фаворит, но −1 трудно».

**Куда делся `quality_flag` / низкая мотивация?**  
Жёстко: **Мотивация = нет** в Истории — матч вне обучения; на Отчёте серый (кэфы да, MAE нет).  
Мягко: **`match_weight`** (колонка «Вес»). `note = low_motivation` — только подпись.

**Нужно ли менять знак форы при загрузке?**  
Нет, если это фора **хозяев** как у бука.

**Почему «мало матчей»?**  
Нет полной линии (AH + тотал + 4 кэфа) или пустая выборка сезонов.

**Чем отличается «Нейтральное поле» от «Нейтр. вес»?**  
Нейтральное поле — факт матча: без домашнего преимущества. Нейтр. вес — только ослабление вклада строки при обучении (если нейтраль = да).

**Как отметить дерби?**  
Вкладка **История** → строка матча → **▼ Веса** → **Дерби = да**. В БД пишется `derby_weight = 1`. По умолчанию у всех матчей дерби **нет** (`0`).

**Переобучение после правок в Истории?**  
Да: снова «Загрузить из БД» → «Обучить модель» (оба пайплайна).

**Почему 1X2 и тотал «из разных моделей»?**  
Так задумано: Legacy лучше отдаёт 1X2 с DC; Auto лучше AH/OU с α/ρ. Auto может калиброваться по 1X2 внутри себя — это не меняет то, что на экране 1X2 = Legacy.

**Работает ли aging на вкладке «Линия»?**  
Да, если включён в `model_config.json`: тот же `gmCoreSdLambdas`, `matchDate` = inactive или сегодня.
