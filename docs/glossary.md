# Глоссарий

Единые определения терминов для документации калькулятора честных коэффициентов. Язык документов — русский; обозначения исходов **P1**, **X**, **P2** и **margin** — как в исходной спецификации.

---

## Исходы и коэффициенты

### P1 / X / P2

Исходы линии **1X2** на матч:

| Обозначение | Значение |
|-------------|----------|
| **P1** | Победа команды хозяев (home) |
| **X** | Ничья |
| **P2** | Победа команды гостей (away) |

В расчёте целевого матча **команда A** — хозяин, **команда B** — гость, если не указано иное (нейтральное поле — см. venue).

### Коэффициент (десятичный)

Отношение выплаты к ставке. Имплицитная вероятность без учёта маржи: `p = 1 / k`.

### Честный коэффициент

Коэффициент, соответствующий вероятности **без маржи букмекера**:

`k_fair = 1 / p_fair`, где `p_fair` — нормализованная вероятность после de-vig (см. [calculation.md](calculation.md), §1).

### Closing odds

**Закрывающие** коэффициенты букмекера на линию 1X2 непосредственно перед началом матча. В модели данных помечаются флагом `closing_odds=true`. Для пересечения (сценарий 2) используются closing odds матчей цепочки A–C и B–C.

---

## Маржа

### Маржа (margin) / overround

Доля «лишней» суммы имплицитных вероятностей относительно 1. Для линии 1X2:

`S = p1 + px + p2`, где `p_i = 1/k_i`. Обычно `S > 1`; overround ≈ `S - 1`.

### De-vig (снятие маржи)

Приведение имплицитных вероятностей к сумме 1. В MVP — **пропорциональный** метод (см. [calculation.md](calculation.md), §1).

### Коэффициент маржи на вывод (1–5)

Параметр UI для отображения линии **с маржой**: дискретные уровни 1…5 соответствуют overround **1%…5%** на итоговую линию (см. [calculation.md](calculation.md), §2 и [open-questions.md](open-questions.md)).

## Сила команд и Venue Type

### Рыночный удельный вес

Относительная оценка силы команды на рынке (`market_weight` в [data-model.md](data-model.md)). Нормализуется по лиге/турниру и входит в **оба** сценария расчёта.

### Venue Type (справочник)

Тип площадки / контекста матча — **справочник** с фиксированными кодами (выпадающий список в таблице Excel):

`regular_home` · `city_derby_home` · `regional_derby_home` · `neutral` · `special`

Каждый код задаёт множители `h_home_team` и `h_away_team` для хозяина и гостя строки. Импорт: [venue_types.csv](examples/venue_types.csv).

**Не путать** Venue Type `city_derby_home` (площадка) с Derby `city_derby` (перевертыш в S2).

## Пересечение и перевертыши

### Пересечение

Ситуация, когда у команд **A** и **B** есть **общий соперник C**. Сила пары A vs B уточняется через матчи A–C и B–C (сценарий 2).

### Общий соперник (команда C)

Третья команда, через которую выполняется пересчёт относительной силы в сценарии 2.

### Перевертыш (FlipRule)

Правило с полями `rule_id`, `condition`, `coefficient`, корректирующее оценку при пересчёте через C. Применяется **только в сценарии 2**.

### Derby (справочник)

Тип дерби / соперничества — **справочник** (выпадающий список в Excel): `no`, `city_derby`, `regional_derby`, `rivalry`, `other`.

В матче хранится `derby_id`. Коэффициент перевертыша `flip_coefficient` — в [derby_types.csv](examples/derby_types.csv). Применяется **только в сценарии 2**; при `no` перевертыш по derby не вызывается.

**Не путать** с Venue Type `city_derby_home` (поправка площадки, S1+S2).

## Сценарии расчёта

### Сценарий 1

Базовый расчёт **без** пересечения через общего соперника и **без** перевертышей. Входы: данные прошлого/текущего сезона, рыночный удельный вес, поправка venue для целевого матча A vs B.

### Сценарий 2

Полный расчёт: **включает весь сценарий 1** + матчи A–C и B–C, closing odds цепочки, пересчёт через C, перевертыши (включая дерби). Рыночный вес входит через базу S1, не заменяется только пересечением.

### Надёжность пересечения

Оценка качества цепочки через C. При ненадёжности выполняется откат на сценарий 1 (см. [scenarios.md](scenarios.md)).

### scenario_reason

Текстовое объяснение для UI: почему выбран сценарий 1 или 2 (например: «нет общего соперника за 90 дней»).

## Прочее

### Группа матчей

Набор матчей команды за сезон (прошлый и/или текущий), используемый для сезонной оценки силы в сценарии 1.

### TimeWindowConfig

Настройки временного окна и порогов для поиска подходящего общего соперника C.

### CalculationResult

Результат расчёта: вероятности/коэффициенты P1/X/P2, номер сценария, причина, идентификатор C (если S2).
