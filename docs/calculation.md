# Расчёт: формулы и примеры

Все формулы для калькулятора честных коэффициентов P1/X/P2. Для каждого раздела: **входы → шаги → выход → краевые случаи → числовой пример**.

Связанные документы: [scenarios.md](scenarios.md), [data-model.md](data-model.md), [glossary.md](glossary.md).

---

## Обозначения

| Символ | Значение |
|--------|----------|
| A, B | Команды целевого матча (A — хозяин по умолчанию) |
| C | Общий соперник (сценарий 2) |
| k1, kx, k2 | Десятичные коэффициенты линии 1X2 |
| p1, px, p2 | Вероятности исходов |
| s_T | Эффективная сила команды T |

## §1. Снятие маржи с линии 1X2 (de-vig)

**Сценарии:** 1, 2 (для любых импортированных и closing odds).

### Входы

- `k1`, `kx`, `k2` > 1

### Шаги

1. Имплицитные вероятности: `p_i = 1 / k_i` для i ∈ {1, x, 2}.
2. Сумма: `S = p1 + px + p2`.
3. Честные вероятности: `p_i_fair = p_i / S`.
4. Честные коэффициенты: `k_i_fair = 1 / p_i_fair`.

### Выход

`(p1_fair, px_fair, p2_fair)` и/или `(k1_fair, kx_fair, k2_fair)`.

### Краевые случаи

| Условие | Действие |
|---------|----------|
| Любой `k_i ≤ 1` | Ошибка валидации |
| NaN / пусто | Ошибка валидации |
| `S = 0` | Ошибка валидации |

### Пример

| Исход | k | p = 1/k |
|-------|---|---------|
| P1 | 2.10 | 0.4762 |
| X | 3.40 | 0.2941 |
| P2 | 3.60 | 0.2778 |

`S = 1.0481`

| Исход | p_fair | k_fair |
|-------|--------|--------|
| P1 | 0.4545 | 2.20 |
| X | 0.2806 | 3.56 |
| P2 | 0.2650 | 3.77 |

Проверка: `0.4545 + 0.2806 + 0.2650 = 1.0001` (округление).

**v2:** методы Shin / power — [open-questions.md](open-questions.md).

## §2. Наложение маржи на вывод (UI 1–5)

**Сценарии:** отображение после расчёта S1/S2.

### Семантика (MVP)

`margin_level ∈ {1, 2, 3, 4, 5}` → overround на линию **M = 1 + margin_level/100** (1% … 5%).

### Входы

- Честные `p_i_fair` (сумма = 1)
- `margin_level`

### Шаги

1. `p_i_margined = p_i_fair * M`
2. `k_i = 1 / p_i_margined`

Подпись UI: «с маржой {margin_level}%».

### Выход

Коэффициенты с маржой; сумма имплицитных вероятностей = M.

### Пример

`p1_fair=0.45`, `px_fair=0.28`, `p2_fair=0.27`, `margin_level=3` → M=1.03.

| Исход | p_margined | k |
|-------|------------|---|
| P1 | 0.4635 | 2.16 |
| X | 0.2884 | 3.47 |
| P2 | 0.2781 | 3.60 |

### Краевые случаи

| Условие | Действие |
|---------|----------|
| `margin_level` вне 1…5 | Ошибка / clamp |
| Режим «без маржи» | M = 1, пропуск шага |

## §3. Рыночная сила команд

**Сценарии:** 1, 2 (в S2 — через базу S1).

### Входы

- `w_T` — рыночный удельный вес команды T за сезон/лигу

### Шаги

1. Среднее по лиге: `w̄ = mean(w_T)` для всех команд турнира.
2. Нормализованная рыночная сила: `s_market(T) = w_T / w̄`.

### Выход

`s_market(A)`, `s_market(B)`.

### Пример

| Команда | w | s_market |
|---------|---|----------|
| A | 1.20 | 1.09 |
| B | 0.90 | 0.82 |
| C | 1.00 | 0.91 |
| Среднее w̄ | 1.10 | — |

## §4. Поправка Venue Type (справочник)

**Сценарии:** 1 (целевой матч), 2 (целевой + матчи A–C, B–C).

### Входы

- Базовые силы `s_home`, `s_away` (хозяин и гость **в строке матча**)
- `venue_type_id` — код из справочника **VenueType** ([venue_types.csv](examples/venue_types.csv))

### Шаги

По коду матча из справочника берутся два множителя:

```
(h_H, h_A) = VenueType[venue_type_id]   // h_home_team, h_away_team

s_home' = s_home * h_H
s_away' = s_away * h_A
```

### Коды справочника (MVP)

| venue_type_id | h_H | h_A (пример) |
|---------------|-----|----------------|
| `regular_home` | 1.08 | 0.92 |
| `city_derby_home` | 1.10 | 0.90 |
| `regional_derby_home` | 1.09 | 0.91 |
| `neutral` | 1.00 | 1.00 |
| `special` | 1.00 | 1.00 |

Коэффициенты в справочнике настраиваются; в таблице Excel пользователь выбирает только **код** из выпадающего списка.

### Пример

Матч: A дома vs B, `venue_type_id = regular_home`.

`s_A' = 1.20 * 1.08 = 1.296`, `s_B' = 0.95 * 0.92 = 0.874`.

**Не путать:** `city_derby_home` (Venue Type) — поправка площадки; `city_derby` (Derby) — тип соперничества и перевертыш в S2.

## §4b. Перевертыши (только сценарий 2)

> **scenario: 2 only** — в сценарии 1 блок **не вызывается**.

### 4b.1. Derby (справочник)

По `derby_id` матча из [derby_types.csv](examples/derby_types.csv):

```
если DerbyType[derby_id].applies_flip_s2:
    k_flip = DerbyType[derby_id].flip_coefficient
    s_side := s_side * k_flip
```

| derby_id | flip (MVP) | S2 |
|----------|------------|-----|
| `no` | — | не применяется |
| `city_derby` | 0.95 | да |
| `regional_derby` | 0.96 | да |
| `rivalry` | 0.97 | да |
| `other` | 1.00 | да (настраивается) |

### 4b.2. Прочие FlipRule

| rule_id | condition | Эффект |
|---------|-----------|--------|
| `team_win` | сторона победила в матче A–C / B–C | `s := s * k_rule` |
| `team_loss` | сторона проиграла | `s := s / k_rule` |

Справочник: [flip_rules.csv](examples/flip_rules.csv) (без строки derby — коэфф. derby в **DerbyType**).

### Порядок применения

1. Рассчитать базовую `r_AC`, `r_BC` из de-vig odds (§6).
2. Venue Type матча (§4).
3. Derby по `derby_id` (§4b.1), если `applies_flip_s2`.
4. Остальные FlipRule по исходу матча (§4b.2).
5. Конфликт правил на один матч → ненадёжно ([scenarios.md](scenarios.md)).

### Пример

Матч A–C, `derby_id=city_derby`, `flip_coefficient=0.95`. `s_A=1.10` → `s_A=1.045`.

## §5. Сценарий 1 — базовый расчёт

**Без** пересечения и **без** FlipRule.

### Входы

- Матчи A и B за текущий/прошлый сезон (коэффициенты 1X2)
- `w_A`, `w_B` — рыночные веса
- Venue целевого матча A vs B
- Параметры: `λ_m` (вес рынка), `β` (вес прошлого сезона), `k_draw`

### Шаги

#### 5.1. Сезонная оценка силы из группы матчей

Для каждого матча команды A против соперника S:

1. De-vig → `(p1_f, px_f, p2_f)`.
2. Implied отношение силы A к S (A дома в матче):

   `r_A/S = p1_f / p2_f`  (если A — home)  
   `r_A/S = p2_f / p1_f`  (если A — away)

3. Вклад в logit-пространстве: `L = ln(r_A/S)`.

Агрегат по матчам A:

`L_A = Σ (ω_m * L_m) / Σ ω_m`, где `ω_m = β` для прошлого сезона, `(1-β)` для текущего.

**MVP:** `β = 0` (только текущий сезон); если текущего нет — `β = 1`.

`s_season(A) = exp(L_A)`, нормализация опциональна к среднему 1 по лиге.

Аналогично для B → `s_season(B)`.

#### 5.2. Слияние с рынком

`λ_m = 0.4` (MVP), `λ_s = 0.6`:

```
s_A = λ_s * s_season(A) + λ_m * s_market(A)
s_B = λ_s * s_season(B) + λ_m * s_market(B)
```

#### 5.3. Venue Type целевого матча

По `venue_type_id` из справочника (§4):  
`s_A' = s_A * h_H`, `s_B' = s_B * h_A`.

#### 5.4. Вероятности 1X2 (упрощённая модель)

Параметр ничьей `k_draw` (MVP: **0.26** или среднее `px_fair` по лиге):

```
p1 = (s_A' / (s_A' + s_B')) * (1 - k_draw)
p2 = (s_B' / (s_A' + s_B')) * (1 - k_draw)
px = k_draw
```

Нормализация: делить на `(p1+px+p2)` при отклонении от 1.

#### 5.5. Коэффициенты

`k_i = 1 / p_i`.

#### 5.6. Запрет

Не вызывать DerbyType / FlipRule, пересчёт через C (`derby_id` в S1 игнорируется).

### Выход

`(p1, px, p2)`, `(k1, kx, k2)`, промежуточные `s_A'`, `s_B'` — база для сценария 2.

### Числовой пример S1

**Данные:** A дома vs B. `h_home=1.08`, `h_away=0.92`. `k_draw=0.26`. `λ_m=0.4`.

| Источник | A | B |
|----------|---|---|
| s_season | 1.15 | 0.90 |
| s_market | 1.09 | 0.82 |
| s после слияния | 1.126 | 0.868 |
| s после venue | 1.216 | 0.799 |

`p1 = (1.216/(1.216+0.799))*0.74 = 0.446`  
`p2 = (0.799/2.015)*0.74 = 0.293`  
`px = 0.26` → после норм.: **p1≈0.479, px≈0.279, p2≈0.315**

**k ≈ 2.09 / 3.58 / 3.17**

## §6. Сценарий 2 — пересечение

Включает **полный прогон §5** → `(p1_0, px_0, p2_0)`.

### Входы

- Результат S1
- Матчи A–C, B–C с closing odds
- Выбранный C
- FlipRule
- `γ` — вес пересечения в слиянии (MVP: **0.6**)

### Шаги

#### 6.1. De-vig closing odds каждого матча цепочки

#### 6.2. Относительная сила через C

Для матча A–C (после venue и flips для сторон в матче):

`r_AC = s_A_in_match / s_C_in_match` из implied odds:

```
r_AC = (p1_f / p2_f)   если A home
r_AC = (p2_f / p1_f)   если A away
```

Среднее по матчам: `r̄_AC` (геометрическое или арифметическое; MVP — **геометрическое**).

Аналогично `r̄_BC`.

#### 6.3. Пересчёт A vs B

```
r_AB = r̄_AC / r̄_BC
s_A'' = sqrt(r_AB)   // калибровка к шкале сил
s_B'' = 1 / sqrt(r_AB)
```

Применить venue **целевого** матча уже учтённому в S1 — для пересечения venue матчей A–C/B–C применяется **до** расчёта `r_AC`, `r_BC`.

#### 6.4. Вероятности по пересечению

Та же модель, что §5.4, с `s_A''`, `s_B''` → `(p1_x, px_x, p2_x)`.

#### 6.5. Слияние с S1

```
p_i = (1 - γ) * p_i_0 + γ * p_i_x
```

MVP: `γ = 0.6` при надёжном пересечении; при откате `γ = 0`.

`k_i = 1 / p_i`.

### Числовой пример S2

**S1:** p1_0=0.48, px_0=0.27, p2_0=0.25.

**Цепочка:** один матч A–C: k=(1.90, 3.50, 4.20) → p1_f=0.454 → r_AC≈1.20.  
B–C: k=(2.40, 3.30, 2.90) → r_BC≈0.95.

`r_AB = 1.20/0.95 = 1.263` → после модели: **p1_x≈0.52, px_x≈0.26, p2_x≈0.22**.

**Слияние (γ=0.6):**

| | p1 | px | p2 |
|---|-----|-----|-----|
| S1 | 0.48 | 0.27 | 0.25 |
| Xsect | 0.52 | 0.26 | 0.22 |
| **Итог** | **0.504** | **0.264** | **0.232** |

**k ≈ 1.98 / 3.79 / 4.31**

### Пример отката S2 → S1

CV оценок r_AC = 0.32 > 0.25 → ненадёжно → `γ=0` → итог = S1 (0.48, 0.27, 0.25).

## §9. Псевдокод

```
function calculate_match(team_a, team_b, match_date, venue, config):
    candidates = find_common_opponents(team_a, team_b, match_date, config.window)
    suitable = filter_suitable(candidates, config)
    best = argmax_reliability(suitable)

    base = scenario1(team_a, team_b, venue, config)  # §5

    if best is None or not is_reliable(best, config):
        return Result(
            probs=base.probs,
            scenario=1,
            reason=reason_code(...),
            common_opponent=None
        )

  xsect = scenario2_intersection(team_a, team_b, best, venue, config)  # §6, §4b
    gamma = config.merge_gamma if is_reliable(best) else 0
    probs = (1 - gamma) * base.probs + gamma * xsect.probs

    return Result(
        probs=probs,
        scenario=2,
        reason="S2_OK",
        common_opponent=best.id
    )

function display_odds(probs, margin_level, mode):
    if mode == "fair":
        return 1 / probs
    if mode == "margined":
        M = 1 + margin_level / 100
        return 1 / (probs * M)
```
