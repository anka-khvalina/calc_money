# Требования

Функциональные и нефункциональные требования к десктоп-калькулятору честных коэффициентов P1/X/P2.

---

## 1. Цель продукта

Рассчитывать предсказуемые **честные коэффициенты** на исходы матча **P1 / X / P2** на основе:

- архивных закрывающих коэффициентов (ручная загрузка, предварительное снятие маржи);
- рыночной оценки относительной силы команд;
- поправок на место проведения (дом / выезд / нейтраль);
- при наличии надёжного пересечения — пересчёта через общего соперника и правил перевертышей.

**Базовое определение:** честный коэффициент = `1 / честная_вероятность`.

---

## 2. Сценарии расчёта (раздел 2 спецификации)

Два основных сценария. Приоритет: **сначала** проверка пересечения; при отсутствии подходящего или надёжного C — только сценарий 1.

| | Сценарий 1 | Сценарий 2 |
|---|------------|------------|
| **Название** | Без пересечения через общего соперника | Через пересечение |
| **Когда** | Нет подходящего C в заданном окне **или** пересечение ненадёжно | Есть подходящий C, пересечение надёжно |
| **Рыночный удельный вес** | Да | Да (через полную базу S1) |
| **Дом / выезд / нейтраль** | Да — для целевого матча A vs B | Да — база S1 + venue матчей A–C / B–C |
| **Перевертыши** | **Нет** | **Да** (вкл. коэфф. дерби) |
| **Связь** | Базовый расчёт | **Включает весь сценарий 1** + пересечение и перевертыши |

Подробная логика выбора: [scenarios.md](scenarios.md). Формулы: [calculation.md](calculation.md).

### 2.1. Сценарий 1 — состав входов

- данные **прошлого сезона** (при наличии);
- данные **текущего сезона** (при наличии);
- рыночный **удельный вес** команд;
- поправка на **место проведения** целевого матча (дом / выезд / **нейтраль**).

**Исключено:** перевертыши DerbyType и любые `FlipRule` — **не вызываются** в сценарии 1, даже если `derby_id ≠ no`.

### 2.2. Сценарий 2 — состав входов

**Из сценария 1 (всегда):**

- прошлый / текущий сезон;
- рыночный удельный вес A и B (вес C — при агрегации нескольких кандидатов, см. [data-model.md](data-model.md));
- venue для **итогового** матча A vs B.

**Дополнительно:**

- матчи **A vs C** и **B vs C** в временном окне;
- архивные **closing odds** этих матчей;
- справочник **Derby** (`derby_id` → `flip_coefficient`) и прочие `FlipRule`;
- пересчёт силы через третью команду C;
- venue для каждого матча цепочки A–C / B–C.

Итог сценария 2 = слияние результата сценария 1 с оценкой по пересечению (веса — [calculation.md](calculation.md), §6; допущения — [open-questions.md](open-questions.md)).

## 3. Каскад данных (приоритет источников)

| Сущность | Назначение | Приоритет / MVP |
|----------|------------|-----------------|
| Коэффициенты прошлых сезонов | Ручная загрузка, de-vig | Низший (вес сезона настраивается) |
| Коэф. силы прошлого + текущего сезона + дата | Группа матчей | Обязательно для группы |
| Рыночные коэффициенты силы (удельный вес) | Относительный вес | **Сценарии 1 и 2** |
| Поправки venue | Дом / выезд / нейтраль | Обязательно |
| Коэффициенты перевертышей | `FlipRule` | **Только сценарий 2** |

## 4. Пользовательские сценарии

### UC-1: Импорт данных

1. Пользователь загружает CSV (матчи, силы, venue, при необходимости flip rules).
2. Система валидирует и показывает ошибки.
3. Данные сохраняются локально.

### UC-2: Расчёт матча

1. Пользователь выбирает команду A (хозяин) и B (гость).
2. Задаёт venue целевого матча (дом A / нейтраль / гость A).
3. Опционально настраивает временное окно поиска C.
4. Нажимает «Рассчитать».
5. Система выбирает сценарий 1 или 2, считает честные вероятности и коэффициенты.

### UC-3: Просмотр результата

1. Пользователь переключает режим: без маржи / с маржой (1–5) / табличный вид.
2. Видит бейдж «Сценарий 1» или «Сценарий 2», `scenario_reason`, при S2 — общего соперника C.
3. Таблица 2×3: строки — команды, столбцы — P1, X, P2 (семантика — [ui-spec.md](ui-spec.md)).

---

## 5. Вывод и маржа

- Режим **без маржи:** честные коэффициенты после de-vig и расчёта сценария.
- Режим **с маржой:** наложение overround по уровню 1–5 (см. [calculation.md](calculation.md), §2).
- Округление отображения: **2** знака после запятой.
